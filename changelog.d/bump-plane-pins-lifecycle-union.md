兩個平面 pin 升級並補上 lifecycle 詞彙分歧的修復：`paulsha-cortex` 由 `3dfea79`（v0.1.0 時期、落後 main 613 個 commit）升至 `ea4cd53`，`paulsha-hippo` 由 `eb2ccb8` 升至 `96513bc`。**為何成對移動**：兩平面的 lifecycle 詞彙表必須逐字相等（本 repo 的 `tests/test_cortex_alignment.py::test_cortex_phases_match_hippo_schema` 是那條契約唯一的守門人，因為兩者之間刻意零 import 依賴），升其中一個而不升另一個必 FAIL，故已在 `pyproject.toml` 的 pin 上方寫明此約束。**修掉的分歧**：cortex 於 `ae4bc43` 把首階段由 `research` 改名為 `claim`（該階段在 cortex 是 work item 認領、manager 決定性執行，與 hippo 的記憶 slice 調查階段語意不同），hippo 未跟進，對齊測試自此 FAIL；上游採**詞彙聯集**而非任一側改名（hamanpaul/paulsha-cortex#376、hamanpaul/paulsha-hippo#126），兩邊 `PHASES` 同為 `("claim", "research", "define", "plan", "build", "verify", "review", "ship")`，hippo 既有 235 個 `phase: research` slice 零遷移仍合法，cortex 的執行序列 `WORKFLOW_PHASES` 維持 7 個不變。
- `tests/test_stage3_lifecycle_mvp.py`：`GoldenSliceTests` 的 `artifact_kind_by_phase` 直接迭代 `schema.PHASES`，詞彙聯集後缺 `claim` 鍵會 `KeyError`；補上 `claim → task`（gate 只各別驗 `phase ∈ PHASES` 與 `artifact_kind ∈ ARTIFACT_KINDS`，無配對約束，`task` 對應認領記錄的語意）。
- `tests/test_stage11_operator_cockpit.py`：cortex v0.1.3 起 `control/client.read_status()` 新增「status 帶 daemon pid 但該 pid 不存活 → `degraded="dead"`」分支，舊版會退回看 `updated_at` 新鮮度而把死掉的 daemon 判為健康；`test_manager_tick_round_trip_refreshes_open_modal_from_status` 用的假 pid `4321` 因此讓 modal 讀到 degraded 狀態。改用 `os.getpid()` 讓 liveness 檢查通過，斷言 focus 留在「tick 後 modal 會吃到刷新的 status」這件本來要驗的事上。
