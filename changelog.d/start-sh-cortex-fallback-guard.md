### Fixed
- `scripts/start.sh` 不再因為「cortex manager 已經在跑」而中止啟動。實際情境：systemd user session 活著且 `cortex-manager.service` 常駐，但發動 start.sh 的非 login shell 沒有 `XDG_RUNTIME_DIR`，`systemctl --user` 便以 `Failed to connect to bus` 失敗、被判成 systemd 不可用而走 local fallback；fallback 起的第二份 manager daemon 搶不到 `~/.agents/control/manager.lock`（`manager_daemon.run_loop` 拿不到 flock 就 `return False`，靜默退出、log 為空），cockpit 前的 gate 因而判定啟動失敗 `exit 1`，cockpit / telegram / dream / cost 全被 trap 清掉。兩處各自修補：新增 `ensure_xdg_runtime_dir()` 在 `start_lock` 之前補回 `/run/user/$(id -u)`（`start_lock` 也吃這個變數，晚補會讓同一台機器出現兩個 lock 路徑而破壞 single-instance）；fallback 起 daemon 前先以 `cortex_manager_lock_is_held()`（`flock -n -E 100` 探測，以 kernel 鎖狀態為準，陳舊 lock 檔仍判為 free）與 `cortex_monitor_is_running()` 判斷該角色是否已有人承擔，是則跳過且不設對應 PID。cockpit 前的兩個 gate 抽成 `verify_cortex_fallback_alive()`，只檢查本輪 fallback 自己起的進程——PID 未設代表刻意跳過，不是啟動失敗。順帶讓 fallback monitor 不再與既有 monitor 疊起來搶同一份 state。
